Configuration — Permission Pattern Matching

how allow / deny patterns resolve against tool calls

Configuration Structure
✅ permissions.allow
Tools that run without prompting. Evaluated first — if a tool call matches any allow rule, it proceeds silently.
🚫 permissions.deny
Tools blocked entirely. Deny rules override allow. If neither matches, user is prompted to confirm.
pattern syntax varies by tool type
Built-in Tools — Read, Glob, Grep, Edit, Write, WebFetch
PatternMeaningExample
Read Allow all reads — bare name, no parens matches Read(any/path)
Read(**) Treated as path pattern, NOT "all files" broken does not match Read(~/file.yaml)
Read(/src/**) Path glob — recursive match under /src/ matches Read(/src/a/b.ts)
Key rule: bare tool name = allow everything. Parentheses are only for restricting to specific paths via patterns.
bash has special word boundary rules
Bash Tool — Word Boundary Matching
PatternMatchesDoes NOT MatchWhy
Bash(ls *) ls, ls -la, ls -R /tmp lsof, lsblk Space before * enforces word boundary
Bash(ls*) ls, ls -la, lsof, lsblk — No space = prefix match, no boundary
Bash(ls) only literal ls ls -la Exact match only — too narrow
Bash all bash commands — Bare name = allow everything
✅ Correct Convention
"Bash(cat *)"
"Bash(ls *)"
"Bash(git *)"
"Bash(grep *)"
❌ Common Mistakes
"Bash(cat)" — won't match cat file.txt
"Bash(ls*)" — also matches lsof
"Bash(*)" — same as bare Bash
tool namespacing
Tool Namespacing — Server Wildcard Only
PatternResultExample
server__* works All tools from server Matches server__getTool
server__getTool works Exact tool name Matches only that specific tool
server__get* broken Prefix pattern fails Does NOT match getTool
server__search* broken Prefix pattern fails Does NOT match searchItems
Wildcard rule: * only works directly after __. Partial-name prefixes like get* or search* silently fail to match. Use the full server wildcard or list each tool individually.
resolution flow
How a Tool Call is Resolved
1️⃣
Check Deny List
If the call matches any deny rule → blocked entirely
2️⃣
Check Allow List
If the call matches any allow rule → runs silently
3️⃣
No Match
Neither list matched → user prompted to approve
